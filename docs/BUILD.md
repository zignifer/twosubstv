# Сборка и разработка

Стек: Kotlin, Jetpack Compose for TV, Android WebView. У приложения собственный каталог и управление, а вход и воспроизведение используют обычную пользовательскую сессию сайта. Собственного бэкенда нет.

## Инструменты

- JDK 17+; Gradle Wrapper 8.9 включён в репозиторий с проверкой SHA-256 дистрибутива.
- Android SDK Platform 35, Build-Tools 34.0.0 и Platform-Tools.
- Node.js 22+ и npm для автономных проверок адаптера.
- При работе через Android Studio откройте корень как Gradle-проект.

Настройте SDK стандартным способом через Android Studio / `ANDROID_HOME`. Не коммитьте `local.properties`, ключи или окружение разработчика. На Windows путь проекта без кириллицы упрощает запуск Gradle/JUnit.

```sh
npm ci
npm test
./gradlew --no-daemon testDebugUnitTest assembleDebug
```

В Windows используйте `gradlew.bat`. APK: `app/build/outputs/apk/debug/app-debug.apk`.

Debug по умолчанию использует локальный Android debug-ключ. Если существует `.local-signing/debug.keystore`, используется он — это сохраняет совместимость с прежними личными тестами сопровождающего. Собственные debug-сборки не заменяют подписанный публичный APK без конфликта подписей.

`build.ps1` — вспомогательный Windows-скрипт для ранее настроенного набора инструментов сопровождающего. Он не скачивает JDK/SDK и не обязателен для обычной сборки. Параметр `-ToolsRoot` указывает на этот набор; окружение меняется только на время процесса, для пути с кириллицей используется проверяемая ASCII-junction.

## Изолированная проверка на устройстве

`./gradlew assembleDebug -PisolatedQa=true` собирает внутренний проверочный пакет `app.twosub.tv.qa`. Это позволяет проверить гостевой вход, не выходя из существующего аккаунта пользователя. В публичный релиз этот APK не включается. Удалять после теста можно только этот точно идентифицированный временный пакет.

## Подписанный release APK

Первый публичный выпуск использует постоянный приватный release-ключ, отличный от debug. Создайте **свой** ключ при разработке собственного форка; для обновления существующего публичного приложения нужен исходный ключ издателя. Не генерируйте его заново перед каждым релизом.

Передайте Gradle четыре переменные окружения в рамках процесса:

- `TWOSUB_KEYSTORE` — абсолютный путь к keystore;
- `TWOSUB_STORE_PASSWORD` — пароль хранилища;
- `TWOSUB_KEY_ALIAS` — alias;
- `TWOSUB_KEY_PASSWORD` — пароль ключа.

```sh
./gradlew --no-daemon testReleaseUnitTest assembleRelease
```

Без переменных подписи Gradle может собрать только unsigned release для самостоятельной подписи. Публиковать такой файл нельзя. Секреты не следует передавать через коммит, issue, скриншот или печатаемую командную строку.

Проверьте готовый APK:

```text
apksigner verify --verbose --print-certs app-release.apk
aapt dump badging app-release.apk
```

Публичный пакет должен иметь ID `app.twosub.tv`, API 26+, увеличенный versionCode, `debuggable=false` и ожидаемый SHA-256 сертификата. В release WebView debugging отключён через `BuildConfig.DEBUG`.

Подпишите APK, переименуйте в `2sub-tv.apk`, вычислите SHA-256 и обновите `release.json`, `SHA256SUMS.txt`, CHANGELOG. Публикуйте единственный universal APK в Releases с фиксированным именем. Документация Android: [подпись приложений](https://developer.android.com/studio/publish/app-signing).

## Что проверяется автоматически

- JUnit `HistoryPolicyTest`: группировка по произведению, последняя просмотренная серия, приоритет явного эпизода, выбор первого доступного эпизода.
- JUnit `SeekPolicyTest`: ступени ускорения удерживаемой стрелки, быстрые нажатия до перерисовки UI, границы таймлайна и неизвестная длительность.
- `test-adapter-quality.cjs`: режимы качества/серверов, штатная перемотка, пауза, restart, события загрузки и ограничения профиля совместимости.
- `test-adapter-catalog.cjs`: разбор HTML, рейтинги, обновления, жанры, поиск, пагинация, портретные постеры и типографика субтитров.
- `test-adapter-history.cjs`: авторизованная история сайта, точный эпизод и позиция аккаунта, перемотка назад, временные метки и отсутствие сессии в bridge-событиях.
- `test-adapter-player.cjs`: предпросмотр без сетевых перемоток, одно подтверждение, отмена, сохранение паузы, кадры из sprite, пропуск заставки и защита от запоздалых команд другой серии.
- `tools/check-publication.mjs`: относительные ссылки и картинки документации, публичные файлы, согласованность версии и релизного манифеста.

Это автономные проверки на фикстурах. Они не заменяют проверку актуального сайта, реального QR-входа, кодеков, пульта и длительного просмотра на разных устройствах.
